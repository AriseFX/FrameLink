# 传输协议

FrameLink 支持 NDI、TCP 和 UDP。NDI 由运行库处理发现、编码和传输；本文描述 TCP / UDP 的 JPEG 数据格式，供接收端实现和调试使用。

## 连接

FrameLink 是发送端。TCP 模式主动连接接收端，UDP 模式向指定地址发送数据报。接收端需先绑定监听地址和端口。

目标格式为 `IPv4:端口` 或 `[IPv6]:端口`，不执行 DNS 查询。例如：

```text
192.168.1.20:7878
[fd00::20]:7878
```

默认目标 `127.0.0.1:7878` 用于本机测试，端口可以修改。TCP / UDP 使用系统路由，不受应用中的 NDI 网卡设置影响。协议不提供自动发现、认证或加密。

## 图像格式

每帧为独立的 baseline JPEG，使用 YCbCr 4:2:0 采样。宽高保存在 JPEG 内，质量范围为 1–100，默认 75。没有音频、时间戳、帧号或附加元数据。

JPEG 是有损编码，质量设为 100 也不等于无损。数据量随采集尺寸、画面内容和质量变化。

## TCP

TCP 字节流由完整 JPEG 顺序拼接而成，没有长度字段、自定义帧头或应用层握手：

```text
[FF D8 ... FF D9][FF D8 ... FF D9][FF D8 ... FF D9]...
       帧 1            帧 2            帧 3
```

TCP 的一次读取可能包含半帧、多帧或跨帧数据。接收端需要保留未完成的字节，按 JPEG 的 SOI（`FF D8`）和 EOI（`FF D9`）标记提取完整图像。FrameLink 生成的 JPEG 不携带自定义元数据；仓库中的标记解析器针对这一格式，不是任意 JPEG 文件的通用解析器。

发送端和参考接收器的单帧上限均为 **2 MiB**。接收实现应设置缓存上限，遇到超大或不完整输入时清理缓存或断开连接。

连接超时为 500 ms。发送启用 `TCP_NODELAY`，默认每帧写入预算为 20 ms，通过短时 socket 超时检查停止请求。写入失败或超时后关闭连接，重新点击“开始发送”可再次连接。系统调用和线程调度可能使实际等待超过设定预算。

## UDP

一个 UDP 数据报包含一张完整 JPEG，没有自定义头，也没有应用层分片、重组或重传：

```text
数据报 1 → [JPEG 帧 1]
数据报 2 → [JPEG 帧 2]
数据报 3 → [JPEG 帧 3]
```

单张 JPEG 最大为 **65,507 字节**。超过限制时发送停止并显示错误，需要降低质量、缩小区域或使用 TCP。

接收端应按实际数据报长度解码，不要将多个数据报拼成一帧。数据报超过链路 MTU 时仍可能产生 IP 分片；任一分片丢失都可能使整帧丢失。协议不包含帧号，无法直接统计网络丢帧或恢复发送顺序。

发送 socket 使用非阻塞模式和 128 KiB 发送缓冲。本机暂不可写时跳过当前帧；界面的丢帧统计只记录这种本地放弃，不统计网络丢失。

## 接收示例

仓库提供一个命令行参考接收器，解析 JPEG 帧并打印吞吐统计：

```powershell
cargo run --locked --release --example receive -- tcp 0.0.0.0:7878
cargo run --locked --release --example receive -- udp 0.0.0.0:7878
```

启动后，将 FrameLink 的目标地址设为这台电脑的 IP 和端口。示例只解析和计数，不显示图像；实现画面显示时，可将提取的完整 JPEG 交给解码器。

相关代码：

- `rust/transport.rs`：JPEG 编码、连接和发送。
- `rust/wire.rs`：大小校验和 TCP 帧解析。
- `examples/receive.rs`：TCP / UDP 接收示例。

## 发送流程与统计

采集、JPEG 编码和传输提交在同一工作线程内顺序执行，不设置应用层视频队列。像素和 JPEG 输出缓冲会复用；固定帧率模式下没有新画面时复用上次编码结果。编码器在支持 AVX2 的 CPU 上使用 SIMD 路径。

“实际发送”统计完整提交给本机 socket 的 JPEG 数量。TCP 连接建立不代表接收端已解码；UDP 没有接收确认，无法据此判断接收端是否在线。

诊断报告中的 `conversion_ms` 包含 JPEG 编码；为保持报告兼容，`ndi_submit_ms` 字段也用于记录 TCP / UDP 提交耗时。`dropped` 表示本机放弃的 UDP 帧数。这些字段不包含接收端解码和显示时间。

## 测试与基准

现有测试覆盖 TCP 拆包和粘包、短写、中断、超时、停止请求、UDP 数据报边界、JPEG 解码、颜色通道，以及超限数据在发送前被拒绝。

本机合成基准的参数为协议、区域边长、目标帧率和运行秒数（1–60）：

```powershell
cargo run --locked --release --example transport_bench -- tcp 512 240 3
cargo run --locked --release --example transport_bench -- udp 512 240 3
```

基准使用变化的纹理和质量 75，输出编码与提交耗时、带宽、接收数和错误。它不包含屏幕采集、物理网络或接收端解码；实际部署应另外测试持续发送、画面颜色、断线恢复和接收帧率。
