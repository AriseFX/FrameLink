# 开发说明

FrameLink `3.1.0-dev` 使用根目录 Cargo 工程构建，应用代码位于 `rust/`，可执行目标为 `FrameLink`。支持 Windows x64 和 macOS 13+ 的采集、颜色转换及 NDI 发送。

## 模块

| 文件 | 职责 |
| --- | --- |
| `model.rs` / `settings.rs` | 参数验证、显示器坐标、设置保存和既有配置导入 |
| `capture.rs` / `capture/picker.rs` | DXGI / GDI、鼠标合成、DPI 坐标与桌面区域框选 |
| `capture_macos.rs` | ScreenCaptureKit、Retina 区域换算、最新帧交接与权限检查 |
| `engine.rs` | 发送线程、启停、异常恢复、统计和预览邮箱 |
| `engine/send_pipeline.rs` / `engine/macos_worker.rs` | 共享 NDI 缓冲生命周期与 Mac 发送循环 |
| `ndi.rs` / `pixels.rs` | NDI ABI 与动态库、发送缓冲、libyuv SIMD 转换 |
| `policy.rs` | 帧率调度、双缓冲选择、恢复间隔与区域边界 |
| `ui.rs` / `tray.rs` | egui 窗口、托盘、参数编辑和状态反馈 |
| `single_instance.rs` | 进程互斥、重复启动通知和已有窗口恢复 |
| `snapshot.rs` | 开发用界面离屏渲染 |
| `benchmark.rs` | 独立的 CPU 转换/复制基准，JSON 输出 |
| `build.rs` / `resource_build.rs` | 编译 libyuv 和 Windows 图标、版本、manifest |

`third_party/libyuv/` 是当前 Rust 程序的颜色转换依赖，构建时静态链接，通过 FFI 调用。`resources/app.ico`、`rust.rc` 和 `rust.manifest` 用于 Windows 可执行文件。

NDI DLL 在后台开始发送时加载。缺失或加载失败时在界面显示错误；采集和 NDI 调用由工作线程处理。设置编辑后约 700 ms 保存，先写临时文件再替换正式文件。

单实例锁按整台机器生效，与可执行文件目录无关。重复启动通过事件唤醒原窗口；窗口只能在原实例所在的交互桌面恢复，前台激活受 Windows 焦点规则约束。进程退出后系统释放锁。开发参数 `--ui-snapshot` 绕过单实例，不影响已运行窗口。

## 采集与发送

- 固定帧率按 `max(previous + interval, now)` 计算下一截止时间，过载时不追赶历史时隙。
- 两份稳定像素缓冲和描述符交替使用，避免改写 NDI 正在使用的数据。退出时先等待 sender 归还缓冲，再释放资源与动态库。
- NV12 无鼠标路径直接将 mapped BGRA 转换为 NV12；BGRX 按实际行距复制。512 方形区域使用 BT.601，640 方形使用 BT.709，超过 1920 / 1080 使用 BT.2020。
- DXGI 暂时不可用时重试；自动模式固定帧率可暂用 GDI。区域超出有效桌面时停止并提示重选。
- 预览最多 2 fps、最大边长 320 像素，只保留一张最新预览。界面可见时统计最多按 10 Hz 刷新，最小化或收到托盘后暂停预览和持续重绘。

NDI 编码、网络、接收端背压和分析队列都可能增加帧龄。界面的平均调用耗时无法代表完整传输延迟，采集等待和 SDK 调用也可能阻塞停止过程。

Mac 使用 ScreenCaptureKit 的 3 槽原生表面池与单槽应用邮箱。回调只替换最新样本，发送线程取出后读回 BGRA，复用内存并转换；慢发送不会在应用内排成视频队列。仅完整帧计入更新数，空闲桌面不补造 240 fps。Mac 的“采集”统计完整样本可用后的 CPU 映射与复制耗时，不计等待下一帧；它不包含桌面合成、回调前延迟或全部 GPU 采集成本。回调时间也不是画面呈现时间或跨机单向延迟。

Apple Silicon 保留 libyuv NEON 和运行时 CPU 检测。构建脚本仅对临时源码中的 I8MM 函数添加目标属性，未全局提高指令集要求。NDI 使用与 Windows 相同的 C ABI，但加载 macOS 动态库；缺少运行库时不会声称开始发送。

Mac 完整包将 NDI 6.3.2 通用运行库放在 `Contents/Frameworks/libndi.dylib`，优先按应用绝对路径加载。打包器默认调用 `fetch_ndi_macos.py` 校验并缓存官方重分发包，不执行安装脚本；运行库保留原厂签名，应用内 `Contents/Resources/Licenses/` 保留许可。`--check-ndi` 只验证动态加载与初始化，不采集或发流。

## 验证

实机采集、NDI 发送和双机延迟未在当前开发环境运行，以下步骤仍需实际设备验收。MSVC 和 Intel Mac 路径需分别构建与运行验证。

3.1.0-dev 已在 Apple Silicon 上通过 28 项单元测试、原生与 Windows GNU 全目标严格 Clippy、两平台 Release 构建及界面快照检查。Mac `.app` 的临时签名、压缩包解压后的可执行权限和 CPU 转换基准已检查；没有将这些结果称为 GUI、屏幕采集或 NDI 发流已实测。

内置运行库的解压包和本机安装副本均已通过 `--check-ndi`：实际加载 `FrameLink.app/Contents/Frameworks/libndi.dylib`，版本为 NDI SDK APPLE 6.3.2.0，初始化成功。检查未采集屏幕或发送视频，不能作为推流或延迟验收。

1. 启动后检查显示器、512 / 640 预设、桌面框选、负坐标副屏和不同 DPI。重启后检查自定义区域与设置保存。
2. 固定 240 fps、DXGI，关闭鼠标与预览，分别使用 NV12 / BGRX 发送同一运动画面。记录接收 fps、CPU、网卡发送率及帧龄分布。
3. 切换预览、最小化、收到托盘、恢复、停止和退出，检查画面连续性与资源释放。切换全屏、显示模式和锁屏，检查恢复或区域越界提示。
4. 发送期间再次启动程序，分别检查普通窗口、最小化和托盘状态：仅保留原 PID，恢复原窗口，源名称、区域与发送任务保持不变。
5. 对比延迟时统一测试画面、接收软件、负载和测量起止点。跨机器时间戳需校时；识别后点击回传测量的是完整控制回路。保留原始样本并检查波动，避免只比较平均值。

Mac 还需验证首次权限拒绝/授权后重启、Retina 的 512 / 640 像素裁剪、多显示器与拔插、停止后重启、NDI 接收格式和实际更新帧率。Mac 关闭窗口直接退出，暂无托盘、单实例通知或桌面框选。Apple Silicon 构建不能验证 Intel Mac 的运行行为。

Windows 单实例自动验收（先退出已运行的 FrameLink）：

```powershell
powershell -ExecutionPolicy Bypass -File tests/SingleInstanceVerification.ps1 -Executable .\dist\FrameLink-3.1.0-dev-Windows-x64\FrameLink.exe
```

脚本随构建包放在 `tests/`，在解压目录运行时可省略 `-Executable`。它检查重复启动、最小化恢复、托盘恢复、并发启动及强制结束后重启，仅清理它创建的进程，不修改设置或自动开始发送。`close_to_tray = false` 时跳过关闭到托盘项。测试时请勿另外启动或操作程序。发送期间的连续性需按上述步骤人工验证。
