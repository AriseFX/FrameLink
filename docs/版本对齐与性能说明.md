## 已对齐的行为与主动扩展

| 行为 | 2.1 源码 | 本轮实现 |
| --- | --- | --- |
| 关闭 / Alt+F4 | 停止并退出 | 收到托盘，保持发送；独立退出路径停止后退出 |
| 托盘创建失败 | 无对应关闭行为 | 保留可见窗口 |
| 精确调度 | 无开关 | 默认关闭，可选最多 0.5 ms 尾段自旋 |
| 精确调度配置 | 无 | 优先读取 2.4.3 的 `lowLatency`，兼容 `precision` 备用键 |
| DXGI 暂时失效 | 显式 DXGI 停机；Auto 永久退 GDI | 分类重建，每秒重试；Auto 固定帧率可临时 GDI；等待可停止 |
| 预览 | 可关，托盘暂停 | 保留，补齐最小化状态判断 |
| 中心区域 | 320 / 416 / 640 | 保留旧索引，末尾追加 512 |
| Windows 图标 / 版本 / DPI manifest | 源码无资源文件 | 恢复图标，版本标为 2.4.4-dev，manifest 纳入构建 |

2.4.3 原产物的首次默认是 60 fps、鼠标开启、预览开启、精确调度关闭。用户已明确 240 Hz 和低延迟用途，本轮首次默认主动改为 240 fps、鼠标关闭、预览关闭，已有配置保留。默认变化与 512 预设属于本轮扩展。

`centerPreset=3` 始终对应 640，新增 `4=512`；`lowLatency` 字符串的原文件偏移为 `0x13666c`，读取调用 VA `0x14000ad5c`，保存调用 VA `0x14000dd1b`。不能将新增 `precision` 键误当作旧版本原键。

## 性能改动及预期作用

1. 固定帧率截止时间改为 `max(previous + interval, now)`。旧算法在处理略超预算时跳到未来槽位，多等一段空闲时间。240 fps、每帧模拟工作 4.20 ms 时，旧调度约 120 fps，新调度约 238 fps。这是确定性调度模型，不是 Windows / NDI 实测成绩。
2. DXGI 桌面内容没更新时，固定模式复用不可变的已生成图像，跳过重复 Map、逐行 BGRA 拷贝和 NV12 转换。NDI 仍按目标节奏提交；这不消除 SDK 自己的编码成本。
3. NV12 且鼠标关闭时，若当次不需要预览，直接从 GPU staging 的 pitched BGRA 内存转到 NV12。开启预览时也只在预览到期的帧走中间 DIB。鼠标显示保留原合成路径。
4. 新图写另一发送槽，重复图重提当前槽而不写像素；下一次异步调用返回后复用前槽，退出前发送空指针 flush。没有额外帧队列。

GPU 到 CPU 的读回和 NDI SDK 的编码、背压仍然存在。当前未实现 GPU 零拷贝、GPU 色彩转换或新的传输协议；不能仅凭显卡型号推断这些阶段的收益。

明确暂时错误才进入 DXGI 恢复；普通参数错误、内存错误等继续报错。Auto 的 GDI 临时回退如果 BitBlt 也失败，则转入无画面等待 DXGI；显式 GDI 失败仍停止。采集区域超出改变后的桌面时停止，要求重新选择。系统重新配置、全屏切换和锁屏后的真实恢复仍需 Windows 验证。

## 验证记录与待测项目

本轮本机完成：MinGW-w64 GCC 15.1.0 Windows x64 Release 交叉编译及链接，项目代码 `-Wall -Wextra -Werror` 语法检查，Clang C++17 平台无关策略测试。构建只出现 vendored libyuv 的两处未使用参数警告。最终新 EXE 的 hash 和依赖清单随分发包的 `build-info.json` 保存。

策略测试覆盖过载帧率、精确等待尾段、暂时 HRESULT 分类、每秒重试，以及重复提交 / 新图 / 预览缓存的双槽选择。它们不替代 D3D11 驱动或真实 NDI DLL 的运行测试。

Windows 自测新增 `size=512` / `size=640`、`precision` / `cursor` / `preview`；NV12 验证还比较带 padding 的输入与紧凑 DIB 的完整输出字节。基准按同一个时间窗口统计发送 / 接收帧率，区分更新提交和重复提交；DXGI 更新仍可能来自采集区域之外，不能称作不同 ROI 图像的精确计数。

`tests/UiVerification.ps1` 覆盖 512 / 640 等预设、多屏主屏选择、旧配置兼容、精确调度持久化、发送中禁用、关窗到托盘继续发送、退出和配置恢复。`tests/RunBenchmarks.ps1` 顺序采集 512 / 640、NV12 / BGRX、普通 / 精确调度组合，避免并行测试争用。

本轮没有 Windows 桌面或用户双机访问，因此 UI 交互、DXGI 实际恢复、图像接收、240 fps 稳态、真实千兆带宽和 AI 端到端延迟尚未测量。原 `延迟实测.md` 保留为历史数据；其中旧版成绩不得当成本轮验收。

下一次 Windows 验收应在同一运动画面、240 Hz、相同区域下比较新旧程序；记录 CPU、网卡发送率、接收帧龄 P50 / P95、识别耗时，并切全屏及停止重启。NV12 / BGRX 最终选择依据真实接收路径，而非仅发送端转换耗时。AI 接收代码不在此仓库，接收队列和推理积压仍需单独核对。
