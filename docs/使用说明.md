# 使用说明

## 安装与启动

从 [Releases](https://github.com/AriseFX/FrameLink/releases) 下载 Windows x64 ZIP，解压后运行 `FrameLink.exe`。升级前先退出旧版；用户设置保存在应用目录之外，替换程序不会覆盖设置。

系统要求为 Windows 10 / 11 x64。MSVC 构建需要 Microsoft Visual C++ 2015–2022 x64 运行库。NDI 模式使用程序同目录的 `Processing.NDI.Lib.x64.dll`；TCP / UDP 模式不加载该 DLL。

## 采集区域

先选择显示器，再选择区域：

- **中心预设**：采集所选显示器中心的 320、416、512 或 640 像素方形区域。
- **桌面框选**：直接在桌面拖动选择区域。
- **手动坐标**：填写位置和尺寸，适合需要固定范围的场景。

坐标以 Windows 虚拟桌面为基准，位于主屏左侧或上方的显示器可能使用负坐标。宽度必须为偶数；NDI 的 NV12 格式还要求高度为偶数。

### 采集方式

| 方式 | 适用情况 |
| --- | --- |
| 自动选择 | 优先使用 DXGI；固定帧率模式下，DXGI 暂时不可用时可回退到 GDI。 |
| DXGI | 采集区域位于单个未旋转显示器内，适合低延迟区域采集。 |
| GDI | 跨显示器、旋转显示器等场景。使用固定帧率。 |

发送统一使用固定帧率。点击“发送帧率”数值可直接输入 1–1000 的整数，新配置默认 300 fps，并开启精确帧间调度。画面没有更新时会重复发送上一帧；填写 300 fps 并不代表显示器会产生 300 张不同画面。

DXGI 在关闭鼠标时会检查更新区域。只发生在采集范围外的变化会复用已有像素，减少回读和转换；发送帧率不变，无需额外设置。

升级时保留原来填写的 FPS，旧版的“跟随刷新率”标记不再生效。更高帧率可能降低传输延迟，也会增加重复帧、编码和接收负载。

修改区域、协议或其他采集参数前，先停止发送。

## NDI 发送

1. 选择 NDI，填写源名称。
2. 选择 NV12 或 BGRX 像素格式，点击“开始发送”。
3. 在同一局域网的 NDI 接收端选择 `电脑名 (源名称)`。

NDI 负责视频编码和传输。FrameLink 将采集画面转换为所选输入格式；BGRX 输入也不代表接收端逐像素无损。

### 图像处理与识别

默认使用 DXGI 优先、NV12、300 fps 和精确帧间调度。提高帧率可能降低传输延迟，也会增加发送和接收负载；关闭精确调度可减少 CPU 占用，但可能增加调度延迟。已有配置保留用户填写的帧率和调度设置。接收线程应及时取帧；识别速度低于输入帧率时，保留最新画面，避免积压旧帧和重复推理。

接收端无需绘制画面即可处理 NDI 返回的像素缓冲。缓冲使用完毕后才能归还给 SDK；异步处理时需要管理其生命周期。输出为原生 YUV 可以减少颜色转换，但模型需要的颜色格式、缩放和归一化仍须处理。

不同分辨率、画面内容和接收设备的结果会不同。项目的测试条件与数据见[延迟测试](延迟测试.md)。

### GPU NV12 转换

在“高级设置”中勾选“GPU NV12 转换（实验性）”。该选项默认关闭，适用于 NDI、NV12、DXGI 或自动采集，并需要关闭“包含鼠标指针”。

GPU 转换保持采集尺寸和固定帧率，不缩放画面。改用 GDI、BGRX、TCP / UDP 或鼠标合成时，应用使用 CPU 路径并保留开关偏好；显卡不支持或初始化失败时也会回退到 CPU。

小尺寸下收益有限。例如 416 × 416 测试中，发送端处理仅缩短约 0.02 ms，尚未确认完整链路延迟稳定下降。建议按实际接收设备和 GPU 负载对比后选择，具体数据见[延迟测试](延迟测试.md)。

### 发送网卡

“自动选择”沿用本机 NDI 配置。多网卡电脑可手动选择有线网卡，点击“应用并重启”，再开始发送。

选择会按网卡标识保存，启动时重新读取 IPv4 地址。网卡断开或 IP 变化后，应检查连接并重新启动应用。界面中的连接速率是网卡协商速率，不是实际发送带宽。此设置只影响 NDI，TCP / UDP 使用系统路由。

## TCP / UDP 发送

1. 在接收端启动相应协议的监听。
2. 在 FrameLink 选择 TCP 或 UDP，填写接收地址，例如 `192.168.1.20:7878`。
3. 设置 JPEG 质量并开始发送。

地址支持 IPv4 和 `[IPv6]:端口`，不支持主机名。默认地址 `127.0.0.1:7878` 仅用于本机接收；跨设备发送时必须改为接收设备的地址和实际监听端口。

JPEG 质量范围为 1–100，默认 75。质量越高，通常需要更多带宽。TCP 连续发送完整 JPEG；UDP 每个数据报包含一张 JPEG，单张不得超过 65,507 字节。UDP 超限时，降低质量或采集尺寸，或改用 TCP。

TCP / UDP 不包含认证、加密和自动发现，适合可信局域网。接收端实现见[传输协议](传输协议.md)。

## 窗口与托盘

默认关闭窗口后收到托盘，发送继续运行。双击托盘图标恢复窗口，右键菜单可停止发送或退出应用。需要关闭程序时，请使用托盘菜单中的“退出”。

再次运行 `FrameLink.exe` 会恢复已有窗口，保留正在进行的发送和当前设置。

## 设置与状态

设置会在编辑后自动保存到：

```text
%LOCALAPPDATA%\FrameLink\settings.toml
```

手动编辑前先退出程序。恢复默认设置时，可以先备份并移走该文件，再重新启动。

| 状态项 | 含义 |
| --- | --- |
| 实际发送 | 已提交给 NDI 或本机 socket 的帧率，不代表接收端已经显示。 |
| 发送端处理 | 采集拷贝、像素转换或 JPEG 编码，以及传输提交的平均耗时。 |
| 采集等待 | 采集接口内的等待耗时，固定帧率下通常接近 0。 |
| 接收设备 | NDI 显示 SDK 连接数；TCP 显示连接状态；UDP 没有接收确认。 |

这些数值用于观察发送端状态。测到接收端像素内存时，还需计入网络和解码；测到实际显示时，再计入接收端绘制和显示输出。识别场景还应单独测量预处理与推理耗时。

## 常见问题

### 启动时提示缺少 DLL

缺少 `VCRUNTIME140.dll` 时，安装 Microsoft Visual C++ 2015–2022 x64 运行库。NDI 初始化失败时，确认已完整解压发布包，且 `Processing.NDI.Lib.x64.dll` 与 EXE 位于同一目录。

### 接收端没有画面

检查双方的网络连接和防火墙。NDI 模式确认源名称和发送网卡；TCP / UDP 模式确认协议、目标 IP、监听端口与接收端一致，接收端已启动监听。

### 提示 UDP 图片过大

降低 JPEG 质量或采集区域尺寸，或者切换到 TCP。UDP 按一包一张图发送，不会自动分片成多个应用层数据报。

### 发送帧率低于设定值

先查看“发送端处理”。处理耗时或网络负载较高时，可以降低固定帧率、缩小采集区域，或在 TCP / UDP 下降低 JPEG 质量。排查时关闭鼠标，以减少额外开销。静止画面会重复发送上一帧，不会主动降到桌面更新率。

### 切换显示器设置后停止发送

分辨率、旋转或显示器连接变化可能使原区域失效。重新选择显示器与采集区域后再开始发送。
